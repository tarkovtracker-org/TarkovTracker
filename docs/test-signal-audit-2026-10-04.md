**Recommendation:** retain the progress, auth, billing, database and runtime contracts. Start with one redundant configuration pin and one copied TaskCard visibility simulation. Bigger fixture or coverage changes need separate evidence.

**Snapshot:** `origin/main` at `6a0c59bf8fdf96d660ce39ed2727d6aa711e8412`, inspected 2026-10-04. The original `refactor/appbar` checkout contained unrelated edits; this report audits the separate clean-main worktree. Those uncommitted changes are outside this snapshot.

**Scope:** 465 tracked executable test files, 104,266 physical lines including fixtures. 392 KEEP, 57 KEEP BUT SLIM, 15 REPLACE, 1 whole-file DELETE proposal. No tests or production code changed. Counts describe the inventory, not success or escape-rate improvement.

## Findings that change the decision

- `app/features/tasks/__tests__/TaskCard.objectivesVisibility.test.ts:10` implements its own refs/watch state and imports no application code. Its three scenarios cannot catch a broken production disclosure. Replace it with one mounted TaskCard journey.
- `app/features/tasks/__tests__/TaskCard.categorizedObjectives.test.ts:25` explicitly recreates the categorizer locally. Production uses `taskCardHelpers.ts:29` through `TaskCard.vue:1013`. Keep the real helper tests; port missing boundaries before retiring the copied suite. The imported objective-type predicate still gives limited real signal, including `useItem`.
- `app/stores/__tests__/useTeamStore.test.ts:235` constructs the database field mapping inside the test. Existing captured realtime callbacks do not check string/null `owner_id` and `join_code`. Replace those four labels with a real callback mapping table before removing them.
- `app/composables/__tests__/useNeededItems.test.ts:383` uses `every`, which passes for empty output; sorting checks re-sort the observed output. Assert independent expected IDs/counts/order before slimming.
- `workers/api-gateway/src/__tests__/configuration.test.ts:9` pins a literal compatibility date. The real workerd smoke loads `wrangler.toml` and exercises the Seasonal progress path. The literal pin adds no runtime compatibility evidence.
- Source/class assertions sometimes protect real incidents, including the Nitro missing-import guard and light-theme contrast regressions. Their brittleness alone does not authorize removal without a rendered/runtime replacement.
