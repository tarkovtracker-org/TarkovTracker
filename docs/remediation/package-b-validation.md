# Package B staging validation boundaries

The candidate is based on the deployed A+C contract. Production deployment and worker scheduling
remain separate approvals. Real Stripe tests use an isolated test account; credentials and synthetic
resource identifiers belong only in ignored local configuration and restricted evidence.

`tests/supabase/stripe-signed-edge.py` requires one authenticated test-mode Stripe CLI listener,
paired local Edge secrets, and the positively identified disposable stack. The expected account is
read from restricted `stripe-test-context.json`, never committed. Signed envelopes stay in memory.
The harness temporarily instruments a disposable copy to observe cloned ingress bytes and inject
faults; the original Request still reaches candidate raw-body signature verification. A per-run
nonce protects the Docker-accessible capture/control endpoint. Candidate runtime source is restored
in `finally`. No signature is generated by the harness.

The signed suite covers valid, invalid, missing, modified-body and duplicate delivery; real provider
truth and ended subscriptions; deferred older events; and lease fencing. Network, 429, 503, malformed
response and 404 cases are controlled injections through the actual Edge processing path, not claims
of observed Stripe outages. The receipt-before-claim scenario explicitly commits the receiver RPC:
normal ingress receives and claims atomically, so this is a recoverable-state fixture, not a claim
that production has a separate receipt commit window. Other crash barriers stop the disposable Edge
process after claim or after application effects, then resume with the original signed envelope.

`stripe-real-deletion.deno.test.ts` exercises real test-mode cancellation, lost-success response,
completion-marker interruption, withdrawal, confirmed subscription end and supported local Auth
deletion. Its transport guard permits only the required provider reads and cancellation-at-period-end
updates. It does not authorize refunds, credits or customer deletion. Discord transport remains
mocked; supported local Auth unlink and real PostgreSQL contention are exercised separately.

The migration and Edge runtime were unchanged by this final transport-validation pass. Earlier
fresh replay, A+C upgrade, timeout rollback/retry, legacy-receipt classification and database lint
results remain applicable to that exact migration hash. Test-only local control hooks, listener
configuration, secrets and captured provider data are not deployment artifacts.

Production observation requires the dedicated read-only observer. Missing observer access does not
justify substituting service credentials. All six historical deletion jobs remain HOLD. The disabled
operating contract still requires a host, alert destination and named operators plus verified delivery
integration before production worker enablement.
